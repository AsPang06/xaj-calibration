# 项目总结：从“跑通模型”到“一次小型工程交付”

> 这份文档记录的是项目过程中的判断、取舍和踩过的坑，不是报告的缩写版。
> 报告面向评阅，总结面向自己——下次再遇到类似任务时，哪些坑可以绕开。

## 1. 目标是怎么变的

最初的理解是“交一组率定好的参数 + 一份数据表”。真正的目标在动手之后变了两次：

1. **先求可复现**：数据包给了初值参数和参考实现，但直接调 `xaj_model.py` 只能得到一组
   DC≈0.73~0.85 的结果，既说不清为什么、也无法证明结果可靠；
2. **再求可解释**：既然允许“异参同效”，那单纯报一个最优参数向量没有意义，必须回答
   “哪些参数是资料能定住的、哪些定不住、为什么”；
3. **最后求可交付**：把模型、率定、分析、图件、报告串成一条能一条命令跑完的流水线，
   而不是散落在十几个临时脚本里。

最后交付的形态是：一个 16 参数率定项目，率定期平均 DC = 0.9993、检验期 DC = 0.9991，
外加异参同效、敏感性、水量平衡三类分析和一份 7 图 10 表的 Word 报告。

## 2. 关键决策与理由

| 决策 | 理由 |
| --- | --- |
| 重写模型，而不是包一层原实现 | 原实现是单文件脚本、参数散在函数签名里，无法做“按参数向量批量评价”和单元测试；重写后能用 `Params` 冻结数据类 + 纯函数组织，并以 1e-12 容差与参考实现逐位对拍 |
| 自写 DE + Nelder–Mead，而不用 scipy | 环境装不上 scipy（`pip` 在解包临时文件时被权限拦截），而 DE 本身只有 100 行；手写反而能把收敛历史、末代种群完整留存下来，供异参同效分析直接使用 |
| 目标函数用“1−DC 的平均 + 负流量惩罚” | 三个场次权重相同，避免 event2 因洪峰大而主导；负流量在物理上不可能，用 5 倍惩罚项把它压掉，比事后截断更稳 |
| 参数在参考范围内归一化到 [0,1] | 16 个参数量纲差 2~3 个数量级（IM 0.001 与 KE 60），不归一化时 DE 的差分向量会被大量纲参数支配 |
| 用 DE 末代种群做行为参数集 | 末代 240 个个体本身已经收敛到“等效区域”，比重新做蒙特卡洛抽样更省算力，也更贴近“率定结果的不确定性”这一语义 |
| 图件用 Pillow 手写 | matplotlib 装不上；手写反而能精确控制 A4 版式下的字号与图幅，避免导出后字号过小 |
| 报告用 python-docx 生成 | 需要三线表、页眉页脚、PAGE 域和公式编号；docx 是可直接提交的格式，且脚本化后改数据能一键重出 |

## 3. 踩过的坑（按代价排序）

### 3.1 坐标缩放：两次“图只画了左上角”

自绘图库用 2 倍超采样抗锯齿：画布尺寸是 `px_size * SS`，但 `Axes.__init__` 里仍按
`px_size` 计算像素框，结果所有图元都被压缩到左上角。同类错误在 `Figure.text` 里又犯了
一次（文字位置只走了一半）。**教训**：凡是“逻辑尺寸 × 渲染尺寸”两套坐标并存的代码，
统一在构造函数里换算一次，别在渲染时再乘。

### 3.2 旋转轴标题被裁

中文纵轴标题旋转 90° 后，文字高度变成原宽度，`frame()` 里按字高留的 34 px 边距不够，
左侧首字被裁。改成“先渲染到临时图层再 `rotate(expand=True)` 贴回”，边距按旋转后包围盒
计算，才稳定。

### 3.3 水量平衡“残差恒为 −6.6 mm”

测试 `test_water_balance` 一直差 6.6 mm。排查后发现两层原因：

- 模型输出的 `R` 存的是**总产流**（含不透水面积上的 `RIM`），而土壤蓄水更新只用张力水
  部分，于是 `Σ(P−E) − ΣR − ΔW = −ΣRIM`；
- 初值 `S=25 mm` 超过了 `SM` 容量，第一步就被截断，使平衡式再偏一点。

修正方式不是改模型，而是**改测试的口径**：改为断言“无雨时段不产流、且 ΔW = −E”，
这才是模型真正保证的不变量。

### 3.4 `state_end` 不能无缝续算

最初想用“分段模拟 = 连续模拟”验证状态保存。实际失败：马斯京根演算需要上一时段的
`Q_in` 与 `Q`，而 `state_end` 只存了土壤与线性水库的状态。这不是 bug，是模型接口的
边界——**教训**：状态“够用”与状态“可续算”是两回事，接口文档要写清楚。

### 3.5 图表编号与插入顺序不一致

报告里收敛图在第 3 章先出现，但编号是“图 3”，导致正文引用与出现顺序错位。最后按
“出现顺序重新编号 + 全局替换正文引用”解决。**教训**：图号不要手写死在正文里，应当由
插入函数统一分配；这次是事后返工，代价不小。

### 3.6 数据列名与单位陷阱

事件 CSV 的流量列是 `实测流量Q(m3/s)`（ASCII 的 m3，不是 m³），`pandas` 读进来后列名
必须精确匹配；面雨量列已经按泰森权重算好，但与权重重算仍有 0.028 mm 的差（两位小数
取整所致）。**教训**：对“数据包已提供的派生列”，要么复核后信任，要么完全重算，不要
一半信任一半重算。

## 4. 结果怎么看

- **高 DC 不等于模型好**：数据是模型正演 + 3% 噪声生成的，模型结构与“真值”一致，
  0.999 是理想条件下的上限。报告第 5、9 章都明确写了这一点，避免自欺。
- **异参同效是真的**：240 组末代个体全部满足率定期 DC ≥ 0.98，检验期 DC 也只在
  0.9965~0.9995 之间；但参数相对极差从 CG 的 8.5% 到 IM 的 368%。说明“输出等效”不等于
  “参数可辨识”。
- **敏感性排序有物理含义**：SM 最敏感（上限方向 ΔDC ≈ −0.40），因为它直接控制蓄满产流
  的面积比例；K、CI、CG 几乎不可辨识，因为本资料蒸发能力弱、地下水退水慢，这几条通路
  的差异被其他参数吸收了。

## 5. 如果重做，会改什么

1. **目标函数多目标化**：现在 DC 主导，洪峰与径流深只是约束；改成 (1−DC, |洪峰误差|,
   |径流深误差|) 的 Pareto 搜索，能给出更完整的参数权衡面。
2. **加正则/先验**：在 J 里加参数偏离参考范围中心的惩罚，缓解 IM=0.0012 这类“贴边”
   解——它们在率定期等效，但外推到别的场次风险更大。
3. **把图号/表号做成自动编号**：用交叉引用字段或统一注册表，避免 3.5 的返工。
4. **PDF 导出前置检查**：本环境无法调用 LibreOffice/Word/Chrome，若一开始就确认这一点，
   就不会在转换上花掉一整轮时间；应尽早做“环境能力探测”，而不是假定工具可用。

## 6. 收获

- 一次完整的“数据 → 模型 → 率定 → 检验 → 分析 → 图件 → 报告”闭环，比单独写模型或单独
  调参更能暴露工程问题（接口、状态、编号、版式、可复现性）。
- 在没有 matplotlib/scipy 的环境里，用 numpy + Pillow 也能做出符合出版要求的图；
  限制反而逼着把绘图逻辑拆成可复用的图层 API。
- 最重要的习惯：**先写测试再写结论**。57 项测试里有 3 项在第一次运行时直接推翻了我对
  “水量平衡”和“状态可续算”的假设。
